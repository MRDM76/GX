# PID 实机测试结果

测试日期：2026-10-01。对象：STM32F103C8T6 + AT8236 + CN1/CN2 编码器电机。

## 结论

两路已完成实机 PI 转速闭环验证，并在相同配置下完成 8 次复测，全部正常结束。使用现有 `Motor/pid.c` 的 `PID_Update` 计算输出，由 `Motor_SetSpeed` 驱动电机，通过 SWD 读取真实编码器采样。

**本报告速度单位为四倍频编码器计数/秒，不是输出轴 RPM。** 实际每圈计数 CPR 尚未标定。以下参数是当前测试条件下的初始参数，不代表所有负载下的最终整定值。

## 实测参数与运行条件

| 项目 | CN1 / CN2 配置 |
| --- | --- |
| Kp | 0.05 |
| Ki | 0.4 |
| Kd | 0（本次采用 PI） |
| 速度输入 | 四倍频编码器计数/秒 |
| 控制输出 | PWM 千分比 |
| 输出限幅 | 0～300，即最高 30% 占空比 |
| 积分限幅 | 0～300 |
| 采样周期 | 约 10ms，积分使用实际 dt（秒） |
| 微分滤波时间常数 | 0.03s；Kd=0 时不参与输出 |
| PWM | 1kHz，快衰减模式 |
| TIM2 | 72MHz 定时器时钟，PSC=19，ARR=3599 |
| 编码器输入 | 内部上拉，正向反馈 sign=+1 |
| 验证方式 | 单路、正向，每轮带动力运行 2 秒 |
| 测试目标 | 3000、6000 计数/秒 |

Kp 单位为“PWM 千分比 /（计数/秒）”，Ki 单位为“PWM 千分比 / 计数”。现有算法内部乘以 dt，不能再将 Ki 预乘采样周期后填入。

机器可读参数：[tuned_counts_pid.json](Motor/hardware/tuned_counts_pid.json)。

## 最新 8 次复测

供电恢复后，两个通道、两个目标速度各重复两次。统计区间为每轮带动力阶段最后 500ms；平均误差 =（平均实测速度 − 目标速度）/ 目标速度 × 100%。表中速度均为计数/秒。

| 通道 | 目标 | 轮次 | 末段平均 | 末段最小～最大 | 平均误差 |
| --- | ---: | ---: | ---: | --- | ---: |
| CN1 | 3000 | 1 | 3000 | 2900～3100 | 0.000% |
| CN1 | 3000 | 2 | 3002 | 2900～3100 | +0.067% |
| CN1 | 6000 | 1 | 6000 | 6000～6000 | 0.000% |
| CN1 | 6000 | 2 | 6000 | 5900～6100 | 0.000% |
| CN2 | 3000 | 1 | 3004 | 2900～3100 | +0.133% |
| CN2 | 3000 | 2 | 3002 | 2900～3100 | +0.067% |
| CN2 | 6000 | 1 | 6002 | 5900～6100 | +0.033% |
| CN2 | 6000 | 2 | 6000 | 5900～6100 | 0.000% |

- 最大末段平均误差约 0.134%，这不是瞬时误差上限。
- 10ms 计数窗口中，单个计数对应 100 计数/秒，反馈存在量化台阶。
- 8 次均为 status=3、fault=0；每次结束四路 PWM 比较寄存器均回到 0。
- 本轮没有复现此前 CN2 的明显降速波动。

汇总文件：[repeat2-summary.json](build/pid-probe/repeat2-summary.json)。原始文件命名为 `build/pid-probe/repeat2-cn{1,2}-{3000,6000}-r{1,2}.json`，包含运行参数、逐次采样和停止状态。`build` 目录由 Git 忽略，清理构建文件前应另行保存所需原始数据。

## 前期对照与异常记录

原来的 20kHz、低占空比快衰减测试未取得持续计数；改用 1kHz 后两路均取得完整反馈，随后切回 20kHz、30% 快衰减又复现无持续计数。因此驱动配置和工作点会影响检测，不能据首轮现象直接判定编码器硬件故障。具体电气原因尚未通过电压、电流波形确认。

此前 CN2 的 6000 计数/秒首轮出现中途降速、输出达到上限后恢复，最后 500ms 范围为 3600～6600、平均 6046；该轮不能仅凭平均值称为稳定。随后复测平均为 6002，范围 5900～6100。异常轮和复测均保留在 `build/pid-probe/cn2-pi6000-1k-v1.json` 与 `cn2-pi6000-1k-repeat.json`。

## 与 RPM 接口的区别

实测诊断直接以计数/秒调用PID内核，未向编码器填入假设CPR。库已增加计数接口。最新串口需求把 `CSGO` 改为0～100%参考速度，两路100%暂定6000计数/秒（非物理最大转速）；原双路RPM接口改名 `Motor_SetTargetsRPM`，单路 `Motor_PIDConfigure` / `Motor_SetTargetRPM` 不变。

获得实际输出轴每圈四倍频计数 CPR 后，可按以下关系换算：

```text
RPM = 计数/秒 × 60 / CPR
Kp_RPM = 0.05 × CPR / 60
Ki_RPM = 0.4 × CPR / 60
Kd_RPM = 0
```

**不要将本报告的 Kp=0.05、Ki=0.4 原样填入 RPM 控制配置。** 换算后仍需结合实际电机负载验证；PWM 频率、衰减模式改变后也应重新测试。

## 当前固件状态与复现

实测结束后已恢复原停机固件并读回确认四路PWM为0。最新串口版本已生成 `build/machinery/machinery.hex`，但没有再次烧录，不能把新构建文件视为板上镜像。正式源码现已改为1kHz/编码器上拉，main.c接入四字符串口百分比速度控制，上电仍保持停止；CPR仍未标定。

只读配置 `Motor_MeasuredCountsPID` 现定义在pid.c，保存本报告参数；计数闭环默认300ms无反馈停机。串口、初始化和参数接入已完成，五组主机测试与ARMCC构建通过，不新增实机记录。具体调用见 [Motor/PID说明.md](Motor/PID说明.md)，接线及四字符协议见 [串口通信.md](串口通信.md)。

测试固件为 `Motor/hardware/pid_probe_main.c`，单独构建，不替换 `Core/main.c`。复现已验证配置可在 MDK-ARM 目录运行，测试名前缀须避免与已有数据重名：

```powershell
python Motor/hardware/probe.py build
python Motor/hardware/probe.py flash
python Motor/hardware/probe.py measure --name new-cn1-pi3000 --channel 1 --mode pid --target 3000 --limit 300 --duration 2000 --pullups --pwm-hz 1000 --kp 0.05 --ki 0.4
python Motor/hardware/probe.py restore
```

本次未验证反向、双路同时运行、长期连续运行或全部负载工况。更多诊断说明见 [Motor/hardware/README.md](Motor/hardware/README.md)。
