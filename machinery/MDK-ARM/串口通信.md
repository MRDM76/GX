# 四字符串口速度控制

## 当前实现

USART1，115200、8N1、无流控。收 ASCII 数字，不是二进制数值。前两位控制 CN1，后两位控制 CN2。

按最新需求，CSGO 的两个参数改为 **0～100% 的期望速度比例**，不再表示 RPM，也不是 PWM 占空比。原双路 RPM 接口保留为 `Motor_SetTargetsRPM`。

四字符中每台只有两位，无法直接表示三位的100。本版暂采用提议的编码：**00～99 线性映射到0～100%，99代表100%**。

```text
电机1百分比 = 前两位十进制数 / 99 × 100
电机2百分比 = 后两位十进制数 / 99 × 100
调用 CSGO(电机1百分比, 电机2百分比)
目标计数/秒 = 百分比 / 100 × 满量程计数/秒
```

每台满量程暂定6000计数/秒（已实测的参考工作点，不是测得的电机物理最大转速），在 `Motor/pid.c` 的 `Motor_FullScaleCountsPerSecond[2]` 修改；两路可分别设置。该定义对应“期望速度/参考速度范围×100”。CPR 未知，不显示虚假的实际 RPM。

| 发送文本 | 传给 CSGO 的百分比 | 目标计数/秒 CN1 / CN2 |
| --- | --- | --- |
| `0000` | 0 / 0 | 两路停止；确认并清除故障锁存 |
| `9900` | 100 / 0 | 6000 / 0 |
| `0099` | 0 / 100 | 0 / 6000 |
| `3060` | 约30.303 / 60.606 | 约1818.18 / 3636.36 |
| `9999` | 100 / 100 | 6000 / 6000 |

直接在 C 中调用 `CSGO(30, 60)` 仍是精确30%、60%，即1800、3600计数/秒；串口两位编码另经过99→100换算。`1000` 表示前两位10、后两位00，绝不表示第一台100%。不支持负数或反向字符。

软件支持表中指令，但历史实测只覆盖单路正向3000、6000计数/秒；低速、双路同时和长时间运行尚未上板验收。不要将100%速度误解为100% PWM：实测 PID 输出仍被限制到300千分比，即30%占空比。

## 分帧与返回

- 推荐每帧发送4个数字后加 LF 或 CRLF，例如 `3060\n`，收到结束符立即执行。
- 也支持严格4个数字、无结束符，收齐后空闲20ms才执行。两帧至少间隔20ms，实际建议100ms。
- 不足4位等待最多100ms；过长、非数字、半帧超时均停机并返回错误。
- 连续 `30600000` 不会猜成两条命令，按超长帧拒绝；要发 `3060\n0000\n` 或分开发送并留间隔。
- 错误后丢弃当前帧到换行或空闲边界，必须发完整 `0000` 确认，再发运动命令。
- 无校验的四字符协议无法识别“一个合法数字被干扰成另一个合法数字”，也无法保证丢字节后自动对齐。结束符、错误停机和超时只是降低风险，正式抗干扰通信仍建议带序号/CRC。

启动返回实际内置参数，例如：

```text
READY UNIT=PERCENT SCALE1=6000 SCALE2=6000 CPS KP=0.050 KI=0.400 KD=0.000 PWM_MAX=300
```

成功设置 `3060` 后返回：

```text
ACK RAW=3060 M1=30.30 M2=60.61 UNIT=PERCENT CPS1=1818.2 CPS2=3636.4 PWM_MAX=300
```

M1/M2 是设置的速度百分比，CPS1/CPS2 是目标计数/秒，**不是实测反馈**；PWM_MAX 的单位为千分比。以上数值仅是按参数计算的示例，不是新一轮电机实测记录。当前没有周期遥测，真实采样仍在 `encoderA/B.counts_per_second`。

常见错误：`FRAME`、`LENGTH`、`PARTIAL_TIMEOUT`、`LINK_TIMEOUT`、`LATCHED_SEND_0000`、`CONTROL`、`MOTOR_SAMPLE_OR_FEEDBACK`、`UART_RX`、`STALE_RX`、`TX_BACKPRESSURE`。错误回执中 M1/M2 为停止后的0，不报告失败指令为执行成功。

## 原理图接线

依据本项目 `原理图.pdf` 第1页：U9第3脚虽然标为 USART2_TX，但实际连 U3第30脚 PA9，应配置 **USART1_TX**；U9第4脚连 U3第31脚 PA10，即 USART1_RX。默认引脚功能可对照 [ST 官方数据手册 Table 5](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)。

| U9 脚位 | 信号 | 连接3.3V USB-TTL |
| --- | --- | --- |
| 1 | VCC_MISC，3.3V支路 | 板子已有电源时不接 |
| 2 | GND | GND |
| 3 | PA9 / USART1_TX | RXD |
| 4 | PA10 / USART1_RX | TXD |

使用3.3V逻辑电平，不接RS-232正负电压或5V TX。保持共地，电机VIN仍需正常供电；USB-TTL不是电机电源，避免给断电板反向供电。GH1.25插座按PCB的1脚标记核对方向，不凭左右位置猜测；图中5/6是固定接地焊脚。本次未测量实物连通性。

不把PA2/PA3改成USART2：它们已用于CN2 PWM。不重映射USART1到PB6/PB7：它们是CN2编码器。板载USB PA11/PA12不等于U9串口，CMSIS-DAP下载通道也不会自动连接U9。

## 固件接入与保护

- `Motor/motor_uart.c` 独立拥有USART1初始化、IRQ及HAL回调：中断收1字节入队，主循环解析；TX为中断异步发送，固定队列保留发送缓冲直到完成，不阻塞PID。
- `main.c` 在定时器和 `Motor_SystemInit()` 后调用 `Motor_UARTInit()`；它自动用 pid.c 的实测参数配置两路计数闭环。主循环只调用 `Motor_UARTPoll()`，其中包含 `Motor_Update()`。
- `Core/tim.c` 和 `.ioc` 已同步为TIM2 PSC=19、ARR=3599、72MHz定时器时钟（1kHz），编码器四路输入上拉；上电保持零速度。
- USART1当前由自定义文件管理，**不要同时再生成另一个 USART1_IRQHandler、huart1 初始化和HAL回调**。若以后迁移到CubeMX的usart.c，应移除自定义硬件初始化/IRQ，仅保留协议层并适配句柄，不能重复初始化。
- EIDE和Keil工程已添加两个新源文件、HAL UART源文件及 `HAL_UART_MODULE_ENABLED` 编译宏。CubeMX重生成Keil工程后需要检查自定义文件和宏是否保留。当前验证使用EIDE+ARMCC5；原uVision工程的其他旧驱动绝对路径未在本次统一迁移。
- 运动中每100ms重发目标；**500ms没有执行成功的完整命令会停止并锁存故障**。无效数据不续租。相同目标重发不清积分。重新运动前发送0000。
- 已有非零PWM却连续300ms无净编码器计数，或采样间隔超过100ms，会停止并锁存。低速可能触发无反馈保护；不能据此区分静止、堵转或断线。
- 接收溢出、UART错误、过旧接收数据、回复队列塞满都会安全停止。队列满时可能无法发送每一条错误回执，恢复空间后补发TX_BACKPRESSURE。
- 软件停止依赖主循环执行；当前没有在正式固件新增IWDG、电流保护或硬件急停。机械安全仍需独立保护。

## 调试方法与验证范围

串口助手选择真实COM口、115200/8N1、文本模式。先发送 `0000\n` 检查ACK，再在安全架空/固定且可立即断电条件下测试单路；运动时每100ms发送一次。停止连续发送后，应在500ms失联期限触发停机；继续前先发0000。

运行 `.\Motor\tests\run_msvc.cmd` 可执行PID、电机、编码器、协议、UART适配五组主机测试。当前均通过，EIDE+ARMCC5全工程24个C文件、1个汇编文件构建成功，输出 `build/machinery/machinery.hex`。**本次未烧录新固件或做实物串口收发测试**；主机模拟测试不等于硬件联调通过。
