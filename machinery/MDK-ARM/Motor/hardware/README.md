# 实机响应采集

`pid_probe_main.c` 是单独构建的诊断入口，不加入 EIDE 正常工程，也不替换 Core/main.c。复用现有 motor.c、pid.c、CubeMX 初始化和 STM32 HAL，通过 SWD 内存命令启动单路测试。

## 最新结论：已完成两路计数速度闭环检测（2026-10-01）

再次复测：用户补充供电后，按相同1kHz与PI配置完成8次单路2秒试验，全部无故障且自动停机。最后500ms的两次平均值分别为 CN1/3000：3000、3002；CN1/6000：6000、6000；CN2/3000：3004、3002；CN2/6000：6002、6000。最大末段平均误差约0.134%，末段瞬时值一般在目标±100计数/秒内。本轮未复现此前CN2明显波动。原始文件前缀为 `build/pid-probe/repeat2-`，汇总为 `repeat2-summary.json`；测试后恢复原停机固件。

后续对照修正了首轮判断：不能因为 20kHz、低占空比快衰减下没有持续计数，就认定反馈硬件故障。原理图中的 PWM 和编码器连接足够通过 SWD 完成闭环试验，无需额外串口。

- CN1：PA15/PB3 经 U7 AT8236 驱动，CN1 的 4/3 脚分别接 PA6/PA7（TIM3）。CN2：PA3/PA2 经 U8 驱动，CN2 的 4/3 脚分别接 PB6/PB7（TIM4）。两个编码器由 U4 的 VCC_MISC 供电，主控使用独立的 U2 VCC；两条电源不能仅凭主控在线就视为全部正常。
- 根据 [AT8236 厂商手册](https://atta.szlcsc.com/upload/public/pdf/source/20230410/6ECF1F3FBCD600EE00816F0DF148575A.pdf) 另测慢衰减方式。CN2 在 20kHz、30% 等效驱动下得到持续 A/B 计数，并以 Kp=0.15、Ki=1、Kd=0 实测跟踪 2000 计数/秒；该组仅用于对照，不是下面统一配置的参数。
- 统一采用 **1kHz、快衰减 PWM** 后两路均得到持续完整的 A/B 反馈；TIM2 PSC=19、ARR=3599，GPIO 使用上拉。1kHz 对照运行完成后再切回 20kHz、30% 快衰减，两路再次因无持续计数退出。由此确认驱动配置/工作点影响测试结果；尚未用电压、电流波形确定具体电气原因。
- 复用实际 Motor/pid.c，通过 PID_Update 计算输出，Motor_SetSpeed 写 PWM；输入为四倍频计数/秒，输出为千分比。没有伪造 CPR 或将结果称为输出轴 RPM。

已实机验证的初始 PI 参数：**Kp=0.05、Ki=0.4、Kd=0**，采样约 10ms、积分范围 0..300、输出范围 0..300（最高 30% PWM）。两路正向反馈符号均为 +1。参数机器可读文件：`tuned_counts_pid.json`。

每轮单路正向带动力运行 2 秒；以下速度为最后 500ms 的样本统计，单位均为计数/秒：

| 通道与轮次 | 目标 | 平均值 | 末段最小..最大 | 平均误差 |
| --- | ---: | ---: | --- | ---: |
| CN1 | 3000 | 3000 | 2900..3100 | 0.000% |
| CN2 | 3000 | 3002 | 2900..3100 | +0.067% |
| CN1 | 6000 | 5996 | 5900..6100 | -0.067% |
| CN2 首轮 | 6000 | 6046 | 3600..6600 | +0.767% |
| CN2 复测 | 6000 | 6002 | 5900..6100 | +0.033% |

CN2 的 6000 首轮中途出现明显降速、PWM 达到上限，随后恢复；不能只凭平均值称该轮稳定。原因未通过电流或负载测量确认，原始数据与复测结果均保留。10ms 计数窗口中单计数对应 100 计数/秒的量化步长。

这是当前实物、当前接线和供电下的短时初步验证，不代表所有负载、反转或两路同时运行都已完成整定。若切换回 20kHz 或其它衰减模式，需重新验证。获得真实 CPR 后，RPM=计数/秒×60/CPR，三个 RPM 增益分别为本配置增益×CPR/60；不可把这组数原样填入 Motor_PIDConfigure 的 RPM 配置。

测试后已恢复原 machinery.hex（CSGO(0,0) 停机版本），Flash 校验成功。正式工程的 20kHz 配置、RPM API 和未标定 CPR 状态保持原样；本次的 1kHz 与 PI 参数仅在诊断固件中验证，未暗中写成正式上电运动逻辑。

原始响应与汇总：`../../build/pid-probe/cn1-pi3000-1k-v1.json`、`cn2-pi3000-1k-v1.json`、`cn1-pi6000-1k-v1.json`、`cn2-pi6000-1k-v1.json`、`cn2-pi6000-1k-repeat.json`、`pid-results.json`。运行 `python Motor/hardware/summarize.py` 可重新计算全部统计。

## 执行

在 MDK-ARM 目录运行；脚本使用本机已配置的 ARMCC 和 EIDE/OpenOCD 安装路径。先确保电机供电、接线、输出轴状态适合短时转动测试。

```powershell
python Motor/hardware/probe.py build
python Motor/hardware/probe.py flash
python Motor/hardware/probe.py measure --name new-cn1-pi3000 --channel 1 --mode pid --target 3000 --limit 300 --duration 2000 --pullups --pwm-hz 1000 --kp 0.05 --ki 0.4
python Motor/hardware/probe.py restore
```

- `open` 的 target 和 limit 单位为 PWM 千分比。`pid` 的 target 单位为编码器计数/秒，直接调用已有 PID_Update；不是输出轴 RPM，不会给编码器填入假设 CPR。
- 每次只测试一路，正向输出；最多 30% PWM、2 秒带动力阶段，前置 200ms 零输出、后置 500ms 零输出采样。无计数 300ms、采样失效或计算错误会停机。
- 使用 IWDG，按标称 40kHz LSI 配置约 500ms 超时；主循环喂狗。该诊断不能替代电流保护或机械防护。
- 开机和测试结束均不自动转动。脚本检查诊断固件标记后才写命令，并检查最终 CCR=0；发现异常运行状态会复位。正常工程仍由 EIDE 原配置构建。
- 状态 1=待命、2=运行、3=完成、4=故障。故障码 1=参数无效、2=初始化失败、3=停止命令、4=采样错误、5=无计数超时、6=反馈方向/运算错误、7=PWM 写入失败。
- `--pwm-hz` 支持 1000 和 20000，默认 20000；复现已验证的 PI 参数必须传入 1000。`--decay slow` 用 IN1 常高、IN2 反向占空比实现厂商慢衰减模式，默认 fast。改变驱动模式后不能直接沿用已测增益。
- 首轮 open-loop 故障不是 PID 整定结果；后续已获得上表的闭环数据，换算 RPM 增益仍需实测 CPR。
